# QTsys 启动器使用说明

QTsys 启动器是面向普通用户的一键入口，适合不想反复打开命令行、手动配置 Token 或手动执行 Git 更新的使用场景。

## 启动方式

推荐在项目根目录双击：

```text
QTsys启动器.exe
```

`QTsys启动器.exe` 是已打包的 Windows 可执行文件，不依赖 `.pyw` 文件关联，双击即可打开。若本地没有该文件，可在项目根目录执行：

```powershell
python scripts/build_launcher_exe.py
```

构建完成后会在项目根目录生成 `QTsys启动器.exe`。

打开启动器后点击 **启动并打开 WebUI**，启动器会自动：

1. 检查 `127.0.0.1:8000` 是否已有后端服务；
2. 未运行时使用当前 Python 环境执行 `main.py`；
3. 等待后端可访问；
4. 自动打开 `http://127.0.0.1:8000`。

如果后端已经运行，启动器不会重复创建进程，会直接打开 WebUI。

## 配置与测试

启动器可以在系统启动前写入本地配置数据库，配置会复用系统现有的加密字段：

- `Tushare Token`：用于真实行情、指数成分和因子/回测数据。
- `AI 大模型`：包括接口地址、模型名称、API Key。
- `MySQL 缓存`：包括主机、端口、用户名、密码、数据库名和是否启用缓存。

密钥字段留空时不会覆盖已保存配置。若本地已经保存过密钥，启动器只显示“已保存”状态，避免明文泄露。

可用测试按钮：

- **测试 Tushare**：调用股票基础信息接口，确认 Token 可用。
- **测试大模型**：向当前模型发送最小请求，确认接口地址、模型和 API Key 可用。
- **测试 MySQL**：执行 `SELECT 1`，确认数据库连接可用。

## 检查更新

启动器的 **检查更新** 页会：

1. 从 GitHub 远程仓库拉取最新引用；
2. 对比本地 `VERSION` 与远程 `config.py` 中的 `VERSION`；
3. 对比本地 commit 与远程 commit；
4. 显示是否落后以及可更新状态。

点击 **开始更新** 后会复用项目现有 `updater.py` 逻辑：

- 若存在本地未提交改动，会先自动 `git stash`；
- 执行 `git pull --rebase`；
- 如果 `requirements.txt` 发生变化，会自动安装依赖；
- 更新前如后端正在运行，启动器会先提示停止后端。

## 注意事项

- 启动器不保存任何明文密钥到代码文件，密钥仍写入系统数据库的加密字段。
- 若双击 `.pyw` 出现“选择应用打开”，请改用 `QTsys启动器.exe`；`.pyw` 仅作为开发环境备用入口。
- 如需重新生成启动器，先确认已安装 `pyinstaller`，然后运行 `python scripts/build_launcher_exe.py`。
- 更新功能依赖本机已安装 Git，并且当前目录是 Git 仓库。
